# 챗봇

메뉴 **챗봇** (`#/chat`)과 모든 화면 오른쪽 아래의 **챗봇 버튼**. 수집한 자료에 자연어로 묻거나 요청하면 근거 링크와 함께 답합니다.
권한은 VIEWER 이상이고, 대화는 **만든 사람만** 봅니다(관리자도 남의 대화는 404).

## 이 탭에서 하는 일

**챗봇을 여는 세 가지 방법** — 셋 다 같은 대화 목록·API를 쓰고, 어디서 이어 써도 같은 대화입니다.

| 어디서 | 어떻게 보이나 |
| --- | --- |
| 오른쪽 아래 **챗봇 버튼** (모든 화면, LLM이 설정돼 있을 때) | 화면 위 대화창 (데스크톱 400×600, 폭 600px 이하에서는 화면 전체). 다른 화면으로 옮겨도 대화창과 기다리던 답이 그대로입니다. 근거의 원문은 새 탭으로, 화면 바로 가기(`#/issues/…` 등)는 뒤 화면만 바꿉니다. 머리의 **새 대화 · 대화 목록 · 크게 보기 · 새 창으로**, `Esc`·×로 닫기 (닫으면 버튼으로 포커스). 열림 상태와 사용자별 마지막 대화는 브라우저(localStorage)에 기억해 새로 고침해도 다시 엽니다 |
| 메뉴 **"챗봇"** (`#/chat`, `#/chat/{id}`) 또는 대화창의 "크게 보기" | 왼쪽 대화 목록과 넓은 대화 영역. 이 화면에서는 떠 있는 버튼을 감춥니다 |
| 대화창·전체 화면의 **"새 창으로"** | 챗봇만 있는 작은 브라우저 창(`chat.html#{id}`, `#new`는 새 대화). 화면 바로 가기는 원래 창의 화면을 바꾸고, "크게 보기"는 원래 창의 챗봇 화면으로 옮깁니다. 팝업이 막히면 대화창에 허용 안내가 뜹니다 |

- 질문을 넣고 Enter(Shift+Enter는 줄바꿈). 빈 화면에는 인사 한 줄, 주요 키워드 칩, 예시 질문 카드 4개, "네이버 - 검색어" 사용법 한 줄이 있습니다.
- 답을 기다리는 동안 "생각 중" 표시(점 세 개 + "질문을 살펴보는 중…" → "수집 기사 검색 중…" → "근거를 정리하는 중…" → "답을 쓰는 중…", 3초부터 경과 초).
- 답의 `[n]`은 근거 칩입니다. 마우스를 올리면 제목·언론사·날짜 미리보기, 누르면 원문 새 탭(이슈는 이슈 화면). 답 아래 "근거 N건"(5건 넘으면 접힘),
  사용한 도구와 화면 바로 가기, 답마다 **복사** 단추(답 + 근거 제목·주소).
- 상단 사용자를 바꾸면 대화창·새 창은 그 사용자의 마지막 대화(없으면 새 대화)로 바뀝니다. 답을 기다리는 동안에는 "크게 보기"·"새 창으로"를 잠시 막습니다
  (답이 지금 창에만 그려지므로).

**입력 바로 가기 두 가지** (입력창 아래 한 줄 안내: "키워드만 입력 → 수집 기사 바로 검색 · 네이버 - 검색어 → 네이버 결과만"):

| 입력 | 동작 | 저장·LLM |
| --- | --- | --- |
| **키워드만** — `반도체`, `삼성전자 DS`, 주요 키워드 칩 클릭 | LLM을 거치지 않고 `search_documents`와 같은 검색(하이브리드, 의미 검색이 없으면 최신순)을 최근 **7일**에서 하고 낱말이 든 기사가 없으면 **30일**로 넓혀 10건까지 답합니다. 답 머리에 "‘반도체’ 관련 최근 7일 기사 N건", 기사마다 근거 번호·제목(원문 링크)·언론사·시각, 뜻만 가까운 기사는 뒤에 따로, 끝에 `네이버 - 반도체` 단추. 0건이면 "네이버에서 찾아보기: 네이버 - 반도체". "문서 화면에서 더 보기" 바로 가기. 답에 "AI 없이 바로 검색" 꼬리표 | 대화·근거는 저장(우리 수집 데이터). LLM 호출 0번(`meta.llmCalls` 0, `mode` KEYWORD). LLM이 설정되지 않아도 됩니다. 다음 질문 때 LLM은 이 답을 지난 대화로 보고, "1번은 어디 기사야?"의 `[1]`은 이 답의 근거를 이어 씁니다 |
| **`네이버 - 검색어`** — `네이버 - 닌텐도`, `네이버-닌텐도`, `네이버: 닌텐도`, `네이버 뉴스 - 닌텐도`, `네이버 닌텐도` | 화면이 `GET /api/v1/naver/news?sort=date`를 직접 불러 대화 안에 **임시 카드**로 그립니다: 제목(원문 새 탭)·언론사·시각·요약 문장·네이버에서 보기, 10건씩 더 보기, "NAVER 검색 결과 · 표시 전용 · 저장 안 함", "네이버 뉴스 탭에서 보기"(`#/naver?q=`). 키가 없거나 INVALID이거나 모드가 off면 카드에 안내만 | **서버 대화로 보내지 않습니다**: 사용자 입력도 결과도 `chat_message`·`chat_citation`에 남지 않고 LLM에 가지 않으며, 새로 고치면 사라집니다(네이버 탭과 같은 감사 로그 `NAVER_SEARCH`만). 옛 화면 등으로 이 형식이 대화 API에 오면 저장·LLM 호출 없이 400 `NAVER_DISPLAY_ONLY` |

"키워드만"의 규칙: 물음표·쉼표 같은 문장부호 없이 낱말 1~4개, 40자 이하이고, 요청·질문 말(알려·찾아·보여·해줘·요약·뭐·어디 …), 때 말(오늘·최근·3일 …),
허브 기능 말(이슈·감시·등록·구독·목록 …), 인사는 없을 때입니다. 끝의 '기사'·'뉴스'·'관련' 같은 낱말은 검색어에서 뺍니다(`반도체 관련 기사` → `반도체`).
띄어 쓴 `네이버 닌텐도`는 뒤가 키워드만일 때만 네이버 형식이라 `네이버 관련 기사 찾아 줘` 같은 질문은 그대로 LLM으로 갑니다.
키워드가 아닌 질문은 LLM으로 가며, 시스템 프롬프트가 "검색어만 준 경우 되묻지 말고 바로 검색"하게 합니다.

## 어떻게 동작하나

챗봇에 물어보거나 요청하면 LLM이 말을 **도구 호출**로 바꾸고, 조회·등록·권한·중복 판정은 화면과 같은 서비스가 합니다(LLM은 결과를 말로 풀 뿐).
대화·도구 호출·도구 결과·근거는 모두 DB(`chat_session`·`chat_message`·`chat_citation`, V14)에 남습니다.

| 도구 | 하는 일 | 부르는 코드 |
| --- | --- | --- |
| `search_documents` | 하이브리드 검색(낱말 모두 포함 + 뜻이 가까운 문서, RRF 관련도순)·기간(`days`·`since`)·토픽·감시·사이트(`site`: 도메인 또는 이름)·기사 종류(`section`: 연설문·보도자료·정책뉴스, 언론사 섹션)로 문서 찾기, 최대 20건. 문서마다 `match`(낱말·의미·낱말+의미)와 `section`. 검색어 없이 사이트·종류만 주면 최신순. 임베딩이 없으면 전문 검색(최신순) | `HybridSearch.search` |
| `list_issues` | 최근 주요 이슈 (언론사 많은 순, 기본 최근 3일·2곳 이상) | `IssueService.list` |
| `list_watches` | 공용 감시 + 내 키워드 감시 (관리자는 전체, 제외된 감시는 뺌) | `WatchService.list` |
| `create_watch` | 키워드 감시 만들기 — 화면과 같은 규칙 (VIEWER는 승인 대기), 등록 요청 채널 `CHAT` | `WatchService.create(..., Channel.CHAT)` |
| `register_source` | 사이트 주소 등록 — 중복·권한 판정, ONBOARD 작업 trigger `CHAT` | `RegistrationService.register(..., Channel.CHAT)` |
| `get_source_status` | 등록·감시 요청 진행 상태와 소스 상태. API 키 대기면 발급 안내(등록 메시지)와 관리자 'API 키' 화면 링크 | `RegistrationService` + 소스 상태 |

- **사실은 도구 결과에서만**: 시스템 프롬프트가 도구 결과에 없는 기사·숫자·상태를 지어내지 말고, 등록·수집 상태는 결과 문장 그대로 전하게 합니다.
- **사이트·기사 종류는 검색어가 아니라 조건**: "정책브리핑 연설문 최근 3개"는 `site=korea.kr, section=연설문, limit=3`(검색어 없음)으로 찾습니다.
  종류 이름(`document.section`)과 사이트 이름은 본문 낱말이 아니어서 검색어에 넣으면 0건이 되기 쉽습니다. 그래서 도구 설명·시스템 프롬프트가 이름을
  조건으로 주고, 사용자가 말한 종류 낱말은 정확한 이름이 아니어도 `section`에 넣으라고 합니다. LLM이 이름을 정확히 모를 때를 위해 ① 종류 이름은 그 사이트의
  실제 이름에 맞추고(같은 이름, 없으면 포함하는 이름: '연설' → '연설문', '브리핑' → '부처 브리핑'·'청와대 브리핑'), ② `site`를 주면 결과 `site_sections`에
  그 사이트의 종류 이름(많은 순 20개)을, 종류 없이 사이트만 주었으면 "질문이 종류를 말했다면 section으로 다시 찾으라"는 `note`를,
  ③ 사이트·종류를 못 찾으면 문서 대신 고를 수 있는 이름(`sites`·`site_sections`)을,
  ④ 검색어 낱말이 하나도 맞지 않았는데 검색어에 종류·사이트 이름이 있으면 "query에서 빼고 section(site)으로 거르라"는 `note`를 돌려줍니다.
  사이트는 도메인(주소를 주면 도메인만, `www.`·대소문자 무시) 또는 사이트 이름(공백 무시)으로 맞추며, 통째로 같은 사이트가 있으면 그것만('한국경제'는
  한국경제TV를 빼고), 없으면 부분 일치하는 사이트 모두입니다. 사이트 이름이 비어 있는 사이트(korea.kr·yna.co.kr 등 초기 등록분)는 도메인으로만 찾습니다.
- **언론 기사는 제목·링크로만**: 언론 기사와 AI 봇을 막은 사이트(`ai_restricted`)의 문서는 제목·분류만 LLM에 보내고, 기사 내용을 요약·추측하지 않게 합니다.
  공공기관·기타 문서는 저장된 요약(300자까지)을 보냅니다. URL은 LLM에 보내지 않고 화면이 번호에 붙입니다(LLM이 주소를 지어낼 수 없다).
- **근거**: 답이 쓴 `[n]`만 `chat_citation`에 제목·링크 스냅숏으로 남깁니다(번호를 안 쓰면 그 턴 도구 결과를 근거로). 도구 없이 답한 후속 질문
  ("2번은 어느 언론사야?")의 번호는 앞 답의 근거를 이어 씁니다. 번호는 답마다 1부터입니다.
- **한 턴의 도구 왕복은 4번까지**(`sensing.chat.max-tool-rounds`), 넘으면 도구 없이(`tool_choice: none`) 지금까지의 결과로 답하게 합니다.
  LLM에는 지난 6턴(`sensing.chat.history-turns`)을 도구 호출·결과와 함께 다시 보여 줍니다(Gemini 3의 `thought_signature`도 그대로 돌려준다).
- **LLM 오류는 대화를 깨지 않습니다**: 429(무료 한도 — 하루 한도면 풀리는 한국 시간, 분당 한도면 몇 초 뒤인지 안내하고, 풀릴 때까지는 LLM을
  부르지 않고 바로 안내 — [llm.md](llm.md#llm-무료-한도-나눠-쓰기))·5xx(한 번 재시도)·시간 초과·키 오류·미설정은 알기 쉬운 문장의 답(주의 색)으로 저장되고,
  그 턴은 다음 질문 때 LLM에 다시 보내지 않습니다. 같은 대화에 답을 기다리는 중 또 보내면 409.
- **API 키는 채팅으로 받지 않습니다**: 키가 필요하면 발급처와 관리자 'API 키' 화면을 안내만 합니다. 채팅에 붙여 넣은 키처럼 보이는 값(`sk-`·`AIza` 접두어,
  16진수 32자 이상, `id:secret`, 32자 이상 영숫자 덩어리)은 저장·LLM 전송 전에 가립니다(대화가 영구 저장되고 외부 LLM에도 가므로 — [../decisions.md](../decisions.md)).
- **키워드만 판정**은 서버 `ChatShortcuts.java`와 화면 `chat.js`에 같은 규칙으로 있고, 사례 파일 `backend/src/test/resources/chat-shortcuts-cases.tsv`로 둘 다 확인합니다
  (`ChatShortcutsTest`, `node scripts/dev/check-chat-shortcuts.mjs`).
- LLM 클라이언트는 추가 의존성 없이 `java.net.http`로 부릅니다(`io.sensinghub.llm`: OpenAI 호환 `chat/completions` + tools, Claude Messages API + tools).
  화면은 `GET /api/v1/chat/status`로 설정 여부와 모델, 문서 검색 방식(`search`: "낱말+의미 (모델/차원)" 또는 "낱말")을 보여 줍니다.

### 의미 검색

전문 검색은 검색어 낱말이 제목·본문에 그대로 있어야 찾습니다. "배드민턴"으로는 "안세영, 덴마크오픈 우승"을, "가정폭력 피해자 보호 장치"로는
"스마트워치 받았지만…전남편에 피습"을 못 찾습니다. 그래서 문서 조각을 **임베딩**(뜻을 숫자 벡터로)해 두고 챗봇의 `search_documents`가
**낱말 일치와 의미 유사도를 함께** 봅니다.

1. **워커**(`embed.py`, 큐가 빌 때 색인 다음 단계): 전문 검색 색인이 만든 조각(`chunk`)을 OpenAI 호환 `/embeddings`로 보내 `chunk.embedding`
   (pgvector `VECTOR(1024)`)을 채우고, 어떤 모델의 벡터인지 `chunk.embed_model`('모델/차원', V15)에 남깁니다. **언론 기사는 제목만**(색인 조각이 원래
   제목 하나), **공공기관·기타 문서는 제목 + 본문 조각**(본문 조각 앞에 제목을 붙여 보냄)이고, AI 봇을 막은 사이트(`ai_restricted`)는 본문 조각을
   외부로 보내지 않고 제목만 임베딩합니다. 호출이 실패하면 아무것도 쓰지 않고 쉬었다가(60초부터 두 배씩, 최대 30분) 다시 하며, 모델을 바꾸면
   모든 조각이 다시 대상이 됩니다. 문서가 다시 색인되면(본문 변경) 새 조각만 다시 임베딩합니다.
2. **백엔드**(`HybridSearch`): 질의를 같은 설정으로 임베딩해 `embed_model`이 같은 조각과 코사인 유사도를 재고(문서마다 가장 가까운 조각,
   하한 0.58), 전문 검색 결과(발행일 최신순)와 **RRF**(문서마다 두 목록의 1/(60+순위) 합)로 합쳐 관련도순으로 줍니다. 두 목록에 다 있는 문서가 맨 앞,
   낱말만·뜻만 맞는 문서가 뒤를 잇습니다. 기간·토픽·감시 조건은 두 쪽에 똑같이 걸립니다.
3. **챗봇**: 도구 결과의 문서마다 `match`(낱말·의미·낱말+의미)를 붙이고, '의미'뿐인 문서가 있으면 "질문과 실제로 관련 있는 것만 쓰라"는 안내를 함께
   보냅니다. LLM에 보내는 내용(근거 번호·제목·분류, 언론 기사 요약 없음, URL 없음)은 같습니다.

**임베딩이 없으면 그대로 전문 검색**입니다: 미설정(`SENSING_EMBED_PROVIDER=none`, 기본), 그 모델로 임베딩된 조각이 아직 없음(질의를 임베딩하지 않아
호출 한도를 아낌), 질의 임베딩 실패(429·5xx·시간 초과·차원 불일치 — 그 뒤 60초는 부르지 않음) 모두 전문 검색 결과(최신순)를 줍니다.
화면의 문서 검색(`/api/v1/documents?q=`)은 전문 검색만 합니다.

### 화면 모양

외부 글꼴·라이브러리 없이 순수 CSS/JS입니다. 코드는 `static/chat.js`(메시지 그리기·보내기·생각 중·근거 링크·대화 목록 공통 부품과 전체 화면),
`static/chat-dock.js`(떠 있는 버튼·대화창·새 창), `static/chat.html`(새 창), 모양은 `static/chat.css`입니다.

- 사용자 글은 오른쪽 말풍선(강조색), 답은 왼쪽에 아바타와 "센싱 봇" 이름, 배경 없는 넓은 본문. 시각은 흐리게 작게.
- 답 본문은 간단한 마크다운(굵게·목록·번호 목록·제목 줄·`코드`·`[글](https://…)`·맨 주소)으로 그립니다(HTML은 모두 이스케이프, 링크는 http(s)만).
  `[n]`은 알약 모양 근거 칩이고 키보드로 가도 미리보기가 뜹니다. 키워드 바로 검색 답은 기사 카드 목록입니다.
- 입력창은 아래 고정, 글에 맞춰 늘어나는 입력칸과 둥근 테두리 안의 보내기 아이콘(빈 칸·보내는 중에는 비활성).
- 오류 답(한도 초과·미설정·시간 초과 등)은 주의 카드로, 제목·도움말은 안내 문구가 아니라 답의 `errorKind`(서버 `meta.error` — `RATE_LIMITED`·`NOT_CONFIGURED`·
  `TIMEOUT` …, 이름에 LIMIT·QUOTA·BUDGET이 들어가면 한도 카드)로 고릅니다. 시간 초과·서버 오류·보내기 실패는 "질문 다시 넣기" 단추.
- 떠 있는 대화창: 열고 닫을 때 투명도·위치 전환(0.18초), 머리는 은은한 그라데이션, 머리 단추는 아이콘(이름은 `aria-label`·`title`).
  네이버 결과 카드도 같은 카드 모양(초록 "N" 표시, "표시 전용" 꼬리표).
- 다크 모드: 시스템이 다크면 챗봇 영역(전체 화면 카드·대화창·새 창·미리보기)만 어두운 토큰(`--c-*`, 밑값은 app.css 토큰)으로 바뀝니다(앱 전체 다크 모드는 아직 없음).
  움직임 줄이기(`prefers-reduced-motion`)면 전환·애니메이션을 끕니다. 375px 폭에서는 대화창이 화면 전체, 예시 카드는 한 줄에 하나.

## 설정

LLM 제공자·모델·키·시간 제한(백엔드·워커 공통)은 [llm.md](llm.md)에 있습니다. `SENSING_LLM_PROVIDER=none`(기본)이면 챗봇 버튼이 보이지 않고,
메뉴 "챗봇"은 "LLM이 설정되지 않았습니다"로 답합니다(키워드만 바로 검색은 LLM 없이 동작).

| 변수 (워커·백엔드 공통) | 기본값 | 설명 |
| --- | --- | --- |
| `SENSING_EMBED_PROVIDER` | `none` | `none`(전문 검색만) \| `openai`(OpenAI 호환 `/embeddings`: Gemini OpenAI 호환 주소·OpenAI·vLLM·Ollama) |
| `SENSING_EMBED_MODEL` | (없음) | 필수. 예: `gemini-embedding-001`(실측), `text-embedding-3-small`, `bge-m3` |
| `SENSING_EMBED_BASE_URL` / `SENSING_EMBED_API_KEY` | (없음) | 주소를 비우면 `SENSING_LLM_BASE_URL`·`SENSING_LLM_API_KEY`를 함께 쓴다 (Gemini처럼 같은 키). 주소를 따로 주면 키도 따로 준다 — LLM 키를 다른 서버에 보내지 않는다 |
| `SENSING_EMBED_DIMENSIONS` | `1024` | `chunk.embedding` 열 크기라 1024여야 한다. `dimensions`를 보내 줄여 받고(Gemini·OpenAI), 모르는 서버가 400을 내면 빼고 다시 보낸다(그때는 1024차원 모델이어야 함) |

| 변수 (워커) | 기본값 | 설명 |
| --- | --- | --- |
| `SENSING_EMBED_BATCH` / `SENSING_EMBED_PER_MINUTE` | `20` / `80` | 한 번에 보내는 조각 수, 분당 보내는 조각 수 상한(0이면 없음) |
| `SENSING_EMBED_TIMEOUT` / `SENSING_EMBED_BACKOFF` | `30` / `60` | 묶음 호출 제한 시간(초), 실패 뒤 쉬는 시간(초, 이어지면 두 배씩 최대 30분) |

| 변수 (백엔드) | 기본값 | 설명 |
| --- | --- | --- |
| `SENSING_EMBED_QUERY_TIMEOUT` | `10` | 질의 임베딩 제한 시간(초). 넘으면 전문 검색만으로 답한다 |
| `SENSING_EMBED_MIN_SIMILARITY` | `0.58` | 의미 후보의 코사인 유사도 하한 (위 실측으로 정함, 모델을 바꾸면 다시 맞춘다). 후보 수(50)·RRF k(60)는 `sensing.search.*` |
| `sensing.chat.max-tool-rounds` / `sensing.chat.history-turns` | `4` / `6` | 한 턴의 도구 왕복 수, LLM에 다시 보여 줄 지난 턴 수 (application 설정) |

이미 쌓인 조각은 유휴 시간에 조금씩 채워지고, 한 번에 하려면 `sensing-embed-backfill [--limit N]`(분당 상한을 지킨다)입니다.
로컬은 `scripts/dev/worker.local.env`에 `SENSING_EMBED_*`를 넣으면 워커와 `run-backend.ps1`이 함께 읽습니다.

## 한계와 주의

- 언론 기사의 내용은 요약·설명하지 않습니다(저장하지 않으므로). 제목·언론사·날짜·분류와 원문 링크로 안내합니다.
- 의미 검색은 임베딩이 채워진 조각에만 동작합니다. Gemini 무료 등급은 분당 100개·하루 한도가 있어 운영 데이터 전체를 채우려면 유료 등급이나 사내 임베딩 모델을 정해야 합니다.
- 남은 것: 대화 요약(`chat_session.summary`)·답 피드백(`chat_feedback`), 화면 문서 검색에도 하이브리드를 쓸지.
- 무료 등급 LLM은 하루 한도가 있어, 다 쓰면 그날은 한국 시간 오후 4~5시까지 안내 답만 나옵니다 — [llm.md](llm.md#llm-무료-한도-나눠-쓰기).
