# 문서

메뉴 **문서** (`#/documents`). 수집한 기사·보도자료·공시를 찾아보는 화면입니다. 권한은 VIEWER 이상입니다.

## 이 탭에서 하는 일

- **기간**(수집 시각 기준: 오늘·3일·7일·전체, 기본 7일)과 **토픽 칩**(토픽별 건수)으로 좁힙니다.
- **검색어**: 제목·본문 전문 검색입니다. 낱말을 모두 포함하는 문서를 찾고, 조사는 떼고 비교합니다("반도체가" → "반도체").
- **사이트**(도메인 또는 사이트 이름)·**기사 종류**(정확히 일치, 입력 후보는 그 사이트의 종류 이름)·**감시 검색어**(정확히 일치)·**소스 ID**로 거릅니다.
  목록의 종류 이름을 누르면 그 사이트의 그 종류로 바로 거릅니다.
- 목록은 발행일 최신순으로 제목·출처·발행 시각·토픽·요약·이슈 링크("이슈 #id (N건)" → [03-issues.md](03-issues.md))를 보여 주고,
  행을 펼치면 본문 일부와 첨부가 보입니다.
- 키워드 감시 화면의 문서 수를 누르면 `#/documents?watch=<감시 ID>`로 넘어와 "이 감시에 걸린 기사"를 봅니다(이때 기간 기본값은 전체).

## 어떻게 동작하나

- **저장 범위**: 언론 기사는 제목·링크·발행일만 저장합니다(저작권). 공공기관·기타 문서는 본문과 첨부 링크도 저장합니다.
  본문 해시가 바뀔 때만 문서 새 버전을 만듭니다.
- **수집 시점 요약·분류**(보강, LLM 설정 시): 워커는 큐에 작업이 없을 때 보강되지 않은 문서를 최신순으로 한 묶음(기본 10건) 가져와 LLM에 한 번에
  보내고, 문서마다 분류 토픽(정책·규제, 입찰·공고, 지원사업, 자사, 경쟁사, 산업동향, 인사·조직, 사건·사고, 기타)과 자유 태그(최대 5개)를
  `document_enrichment`에 둡니다. 공공기관·기타 문서는 본문(앞 4,000자)으로 2문장 이내 요약도 만들지만, **언론 기사는 제목만으로 분류하고 요약은
  저장하지 않습니다.** 수집과 분리돼 있어 LLM 장애는 수집을 막지 않고(아무것도 쓰지 않고 다음 루프에 다시), 응답 검증 실패는 `FAILED`로 남겨
  24시간 뒤 다시 시도합니다. 본문이 바뀌어 문서 버전이 오르면 다시 보강 대상이 되고, 워커 여러 대는 `FOR UPDATE SKIP LOCKED`로 겹치지 않습니다.
  하루 호출 수 상한과 무료 등급 실측은 [llm.md](llm.md)에 있습니다.
- **전문 검색 색인**: 큐가 빌 때 워커가 LLM과 무관하게 아직 색인하지 않은 문서를 200건씩 조각(`chunk`: 제목이 0번, 본문 800자 안팎 최대 20조각,
  언론 기사는 제목만)으로 나누고, 미리 뽑은 낱말(선택 의존성 `nlp`의 Kiwi 형태소 분석, 없으면 조사를 떼는 정규식)을
  `to_tsvector('simple', ...)`로 넣습니다(`index_version` `fts-kiwi-v1`/`fts-regex-v1`). 검색어는 색인 낱말에 접두 일치로 모든 낱말을 찾고,
  아직 색인 전인 문서는 부분 일치로 찾습니다. 색인 직후 같은 사건 기사를 이슈로 묶습니다([03-issues.md](03-issues.md)).
  자세한 원리는 [../how-collection-works.md](../how-collection-works.md)의 "수집 뒤: 인덱싱과 이슈 묶기", 이 방식을 고른 이유는 [../decisions.md](../decisions.md).
- **기간은 수집 시각 기준**입니다("지난번 이후 새로 들어온 것"을 보는 용도). 과거 기사 채우기로 들어온 옛 기사는 수집 시각을 발행 시각으로 두어
  "오늘"에 끼지 않습니다.

## 설정

| 변수 (워커) | 기본값 | 설명 |
| --- | --- | --- |
| `SENSING_ENRICH_ENABLED` | `true` | 수집 시점 요약·분류(보강). 큐에 작업이 없을 때 LLM이 설정돼 있으면 한 묶음씩 돌린다 (`SENSING_LLM_PROVIDER=none`이면 하지 않는다) |
| `SENSING_ENRICH_BATCH` | `10` | 한 번의 LLM 호출에 묶는 문서 수 |
| `SENSING_ENRICH_BODY_CHARS` | `4000` | 문서당 LLM에 보여 줄 본문 글자 수 상한 (언론 기사는 본문을 보여 주지 않는다) |
| `SENSING_ENRICH_DAILY_CALLS` | `300` | 요약·분류의 하루 LLM 호출 수 상한 — [llm.md](llm.md#llm-무료-한도-나눠-쓰기) |
| `SENSING_INDEX_ENABLED` / `SENSING_INDEX_BATCH` | `true` / `200` | 큐가 빌 때마다 색인·이슈 묶기를 한 묶음씩 (LLM 설정과 무관) |
| `SENSING_TOKENIZER` | `auto` | `regex`면 Kiwi가 설치돼 있어도 정규식 분석기를 쓴다 (Kiwi: `pip install -e ".[nlp]"`) |

이미 쌓인 문서는 유휴 틱마다 200건씩 색인되며, 한 번에 끝내려면 `sensing-index-backfill [--limit N]`입니다(2,998건에 약 16초).

## API

```bash
# 수집 문서 (요약·분류·감시 검색어 포함, 발행일 내림차순). since는 수집 시각 기준, topic·keyword·source_id·watch_id·q로 거르고 limit 기본 50·최대 200
curl 'http://127.0.0.1:8080/api/v1/documents?since=2026-10-15T00:00:00Z&topic=정책·규제&keyword=메타넷' -H 'X-User: viewer'
# site: 도메인 또는 사이트 이름, section: 기사 종류 정확 일치 (여러 번 주면 그중 하나, 값 안의 쉼표는 나누지 않음)
curl 'http://127.0.0.1:8080/api/v1/documents?site=korea.kr&section=연설문&section=보도자료&limit=3' -H 'X-User: viewer'
# 상세 (본문·첨부 포함) · 토픽별 건수 · 기사 종류별 건수 (since·source_id·site·topic)
curl http://127.0.0.1:8080/api/v1/documents/1 -H 'X-User: viewer'
curl 'http://127.0.0.1:8080/api/v1/documents/topics?since=2026-10-15T00:00:00Z' -H 'X-User: viewer'
curl 'http://127.0.0.1:8080/api/v1/documents/sections?site=korea.kr' -H 'X-User: viewer'
```

## 한계와 주의

- 언론 기사는 본문과 요약이 없습니다(제목·링크·발행일만). 내용은 원문 링크로 봅니다.
- 화면의 검색어는 전문 검색(낱말 일치)만 합니다. 뜻이 가까운 문서까지 찾는 의미 검색은 챗봇의 문서 검색에만 있습니다([08-chatbot.md](08-chatbot.md#의미-검색)).
- LLM이 설정되지 않았거나 하루 상한에 닿으면 토픽·요약이 비어 있는 문서가 있습니다(다음 날 이어서 채움).
  분류는 정치 발언 기사를 "사건·사고"·"산업동향"에 넣는 식의 오분류가 가끔 있습니다.
- 첨부(HWP/PDF) 텍스트 추출은 아직 없습니다(M4).
